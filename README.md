# global_learning_talent_analytics
# Global Learning & Talent Analytics Dashboard
**Portfolio project | Python + SQL + Power BI + PowerPoint**

An end-to-end, synthetic-data reporting solution designed around learning and talent reporting workflows: recurring reporting, data validation, KPI monitoring, trend analysis, exception management, and stakeholder-ready communication.

> All data is fictional and generated for demonstration. This is an independent portfolio project, not a Deloitte system, client engagement, or representation of Deloitte internal data.

## Business objective
Give a global Learning & Talent team a reliable view of training enrollment, completion, overdue mandatory learning, engagement, course feedback, and data quality across departments and regions.

## Architecture
CSV source files -> Python/Pandas validation & quarantine -> SQLite reporting mart -> Power BI semantic model -> PowerPoint management readout.

## Folder structure
```text
global_learning_talent_analytics/
├── data/
│   ├── raw/                 # fictional source CSVs

```

## Quick start
Requires Python 3.10+.
```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python src/etl.py
python -m unittest discover -s tests -v
```
The pipeline writes `data/learning_analytics.db`, curated CSVs and `etl_quality_summary.json`.

## Power BI setup
1. Run the ETL first.
2. Open Power BI Desktop -> Get Data -> Text/CSV and import the four curated CSVs in `data/processed/`.
3. Create the relationships described in `powerbi/model_setup.md`.
4. Import `powerbi/theme.json` (View -> Themes -> Browse for themes).
5. Add measures from `powerbi/measures.dax` (create each measure separately; calculated column is explicitly labelled).
6. Build the report pages described in `docs/dashboard_design.md`.
7. Save your own `.pbix` file locally from Power BI Desktop. A native PBIX is not generated by this Python project.

## Dashboard pages
- Executive Overview: completion, enrollment, learning hours, feedback, overdue mandatory learning.
- Participation & Completion: monthly trend, department/region matrix, status mix.
- Course Effectiveness: course-level assessment and feedback.
- Data Quality: exceptions by type, exception detail table, curated-vs-raw counts.

## Data quality controls
- Referential integrity: employee and course IDs must exist.
- Non-negative completed hours.
- Feedback range 1-5.
- Assessment score range 0-100.
- Duplicate enrollment IDs quarantined.
- Invalid rows remain in raw source files and are excluded from curated reporting facts; exception details are retained.

## KPI definitions
See `docs/kpi_dictionary.md`. Denominators must be explicit; interpret completion rate as completed enrollments / curated enrollments under current filters.

## Recurring reporting operating rhythm
- Refresh source extracts on agreed cadence.
- Run ETL and review quality summary.
- Resolve or document material exceptions before distributing.
- Refresh Power BI and validate headline totals against SQL.
- Export selected visuals to PowerPoint; include reporting period, refresh timestamp, definitions, caveats and owner.
- Retain versioned output and exception log.

## Testing
```bash
python -m unittest discover -s tests -v
```
Tests check referential integrity, non-negative hours, feedback bounds, and exception detection.

## Limitations / production hardening
This portfolio build uses SQLite and synthetic records. For enterprise deployment, replace SQLite with an approved warehouse, add role-based access controls, managed secrets, audit logging, incremental refresh, formal data contracts, privacy review, reconciliation sign-off, orchestration, monitoring, and documented data retention. Confirm employee-level access rules before publishing.
